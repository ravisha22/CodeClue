## Answer
- Per-call arguments enter the pipeline first in `Session.request()`: the method builds a `Request` directly from the call-site values (`method`, `url`, `headers`, `files`, `data`, `json`, `params`, `auth`, `cookies`, `hooks`) before preparing or sending anything. [(source snippet `request`, `src/requests/sessions.py L502-593`)]
- `Session.request()` then prepares that request and separately computes environment/session-dependent transport settings. It calls `self.prepare_request(req)`, then `self.merge_environment_settings(prep.url, proxies, stream, verify, cert)`, and finally sends with `timeout` and `allow_redirects` taken directly from the current call. [(source snippet `request`, `src/requests/sessions.py L502-593`); (`prepare_request`, `src/requests/sessions.py:459-500`)]
- For `timeout` and `allow_redirects`, the effective value is the per-call value from `Session.request()`. The outgoing `send_kwargs` dict is initialized from those two parameters and then only updated with `merge_environment_settings()` output, which returns `proxies`, `stream`, `verify`, and `cert`—not `timeout` or `allow_redirects`. [(source snippet `request`, `src/requests/sessions.py L502-593`); (source snippet `merge_environment_settings`, `src/requests/sessions.py L752-781`)]
- Environment-derived proxies only participate when `self.trust_env` is enabled. Inside `merge_environment_settings`, environment proxies are gathered only inside `if self.trust_env:`. [(source snippet `merge_environment_settings`, `src/requests/sessions.py L752-781`)]
- When environment proxies are considered, explicit per-call proxy entries beat environment proxy entries key-by-key. The code fetches `env_proxies` and then uses `proxies.setdefault(k, v)`, which fills only missing keys and leaves already-supplied keys in place. [(source snippet `merge_environment_settings`, `src/requests/sessions.py L752-781`)]
- Proxy bypass logic can suppress environment proxy use before those values are merged in. `get_environ_proxies` returns an empty dict when `should_bypass_proxies` says to bypass, and `should_bypass_proxies` returns `True` for URLs with no hostname and for hosts/IPs that match `no_proxy` or system proxy-bypass rules. [(`get_environ_proxies`, `src/requests/utils.py:813-822`); (source snippet `should_bypass_proxies`, `src/requests/utils.py L752-810`)]
- Environment CA-bundle settings only affect `verify` when the per-call `verify` is still `True` or `None`. In that case, `merge_environment_settings` replaces `verify` with `REQUESTS_CA_BUNDLE`, then `CURL_CA_BUNDLE`, then falls back to the current `verify` value. If the caller passed some other value, this branch does not run. [(source snippet `merge_environment_settings`, `src/requests/sessions.py L752-781`)]
- After environment processing, Requests merges transport-related values against session defaults by calling `merge_setting(proxies, self.proxies)`, `merge_setting(stream, self.stream)`, `merge_setting(verify, self.verify)`, and `merge_setting(cert, self.cert)`. That shows the final values for those four settings come from a merge between the request/environment side and the session-default side. [(source snippet `merge_environment_settings`, `src/requests/sessions.py L752-781`); (`merge_setting`, `src/requests/sessions.py:62-89`)]
- Request preparation also merges request state with session state before transport. `prepare_request` explicitly says the `PreparedRequest` has settings merged from the `Request` instance and the `Session`. [(source snippet `prepare_request`, `src/requests/sessions.py L459-500`); (`prepare_request`, `src/requests/sessions.py:459-500`)]

That establishes that both sources are combined and that request cookies are applied after the session-cookie merge step. [(source snippet `prepare_request`, `src/requests/sessions.py L459-500`)]
