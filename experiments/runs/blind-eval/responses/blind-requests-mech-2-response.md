- `Response.iter_content()` is the main streaming entry point. Its docstring says that when `stream=True` is set on the request, it avoids reading the full body into memory at once, which is specifically for large responses. - Chunk-size handling has explicit edge-case rules. `chunk_size` must be an `int` or `None`; if `stream=True` and `chunk_size=None`, data is yielded as it arrives, while if `stream=False`, the content is returned as a single chunk. - For urllib3-backed raw responses, streaming errors are translated into Requests-level exceptions. Inside `generate()`, `ProtocolError` becomes `ChunkedEncodingError`, `DecodeError` becomes `ContentDecodingError`, `ReadTimeoutError` becomes `ConnectionError`, and `SSLError` becomes `RequestsSSLError`. [(source snippet `iter_content`, `src/requests/models.py L801-857`); (`Response`, `src/requests/models.py:642-1041`)]
- If the raw object is not urllib3-like, Requests falls back to repeatedly calling `self.raw.read(chunk_size)` until no chunk is returned. [(source snippet `iter_content`, `src/requests/models.py L801-857`)]
- After the streaming generator finishes, the response is marked consumed by setting `self._content_consumed = True`. [(source snippet `iter_content`, `src/requests/models.py L801-857`)]
- Requests distinguishes between “already consumed and not reusable” versus “already consumed but cached.” If `_content_consumed` is true and `_content` is still a boolean sentinel, `iter_content()` raises `StreamConsumedError`; otherwise it builds `reused_chunks = iter_slices(self._content, chunk_size)` and can iterate cached content again.
