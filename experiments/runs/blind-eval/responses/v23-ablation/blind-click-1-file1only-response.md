# v2.3 Ablation (File 1 Only): blind-click-1
Date: 2026-04-15

Click appears to build the CLI in two stages: decorators first memoize metadata onto Python functions, then command/group objects assemble that metadata into a nested command tree that runtime dispatch walks via contexts and subcontexts.

- The decorator layer is explicit. `command (src/click/decorators.py:168-255)` “Creates a new `Command` and uses the decorated function as ...”, and its behavior is `UNWIND(reversed)`, which strongly suggests Click gathers decorator-added metadata and then applies it while constructing the `Command`. (clue: `command (src/click/decorators.py:168-255)`)
- Parameter decorators attach metadata before command construction. `option (src/click/decorators.py:352-377)` “Attaches an option to the command” and calls `_param_memo`; `argument (src/click/decorators.py:324-349)` also calls `_param_memo`. So options and arguments are not ad-hoc runtime parsing logic on the raw function; they are memoized into command metadata first. (clue: `option (src/click/decorators.py:352-377)`, `argument (src/click/decorators.py:324-349)`, `_param_memo (src/click/decorators.py:314)`)
- The nested CLI abstraction is `Group`. `Group (src/click/core.py:1503-1951)` is “A group ... that nests other commands (or more groups),” extends `Command`, and calls `add_command`, `make_context`, `_make_sub_context`, `fail`, `scope`, `format_commands`, and `_process_result`. That is the clearest statement that nesting is represented as command objects inside a group object. (clue: `Group (src/click/core.py:1503-1951)`)
- Subcommands are registered explicitly. `add_command (src/click/core.py:1622-1630)` “Registers another `Command` with this group” and calls `_check_nested_chain`. That means nested CLIs are assembled by placing `Command` instances under a `Group`, not by scanning functions dynamically at runtime. (clue: `add_command (src/click/core.py:1622-1630)`, `Group (src/click/core.py:1503-1951)`)
- Click validates whether certain nested/chain combinations are legal. `_check_nested_chain (src/click/core.py:73-90)` guards on `base_command.chain`, branches on `register`, is called by `CommandCollection`, `add_command`, and `Group`, and can raise `RuntimeError`. So while building the command tree, Click enforces structural rules about how commands/groups can be nested. (clue: `_check_nested_chain (src/click/core.py:73-90)`, `CommandCollection (src/click/core.py:1961-2014)`, `add_command (src/click/core.py:1622-1630)`)
- At runtime, the clue file points to context-driven dispatch. `Command` is the “basic building block,” while `Group` calls `make_context` and `_make_sub_context`; that implies top-level invocation creates a context for the current command, and descending into a subcommand creates a subcontext for the selected child command. (clue: `Command (src/click/core.py:873-1485)`, `Group (src/click/core.py:1503-1951)`)
- Name resolution for subcommands is group-controlled. `list_commands (src/click/core.py:1784-1786)` returns subcommand names in sorted order, and examples such as `ComplexCLI` and `AliasedGroup` expose custom `get_command` / `list_commands` methods. That suggests runtime dispatch works by asking the current group which subcommand names exist and which concrete command object should handle the next token. (clue: `list_commands (src/click/core.py:1784-1786)`, `ComplexCLI (examples/complex/complex/cli.py:31-45)`, `examples/aliases/aliases.py` index entry, `examples/complex/complex/cli.py` index entry)
- File 1 does not show the exact `invoke` body that consumes argv tokens and calls the chosen callback, so I cannot name every internal step. But the visible structure is: decorators memoize parameters -> `command` turns the function into a `Command` -> `Group` nests commands via `add_command` -> runtime dispatch enters a context/subcontext hierarchy to route control to the right subcommand. (clue: `command (src/click/decorators.py:168-255)`, `_param_memo (src/click/decorators.py:314)`, `add_command (src/click/core.py:1622-1630)`, `Group (src/click/core.py:1503-1951)`)
