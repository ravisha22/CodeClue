# v2.3 Ablation (File 1 Only): blind-echo-mech-1
Date: 2026-04-15

The strongest File-1-only conclusion is that Echo gives static path segments a dedicated early lookup path, while parameterized/wildcard matching happens in the more generic router traversal that follows. The exact parameter-vs-wildcard tie-break is not exposed in this clue file.

- All of these routes compete in the same router. Regular handlers use `Echo.Add`; `Echo.Static` / `Echo.StaticFS` also delegate to `Add`; `Echo.FileFS` delegates to `GET`; and `Echo.File` calls `Add`. So static-file helpers are not a separate routing subsystem—they register into the same route table as ordinary routes. (clue: `Echo.Add (echo.go:642-642)`, `Echo.Static (echo.go:533-533)`, `Echo.StaticFS (echo.go:548-548)`, `Echo.FileFS (echo.go:591-591)`, `Echo.File (echo.go:609-609)`)
- The router lookup path explicitly tries static children. `DefaultRouter.Route(c *Context)` calls `findStaticChild`, `node`, and `find`, and `node.findStaticChild` is its own helper. That is the clearest available evidence that literal/static segments are checked through a dedicated path before falling through to more general node matching. (clue: `DefaultRouter.Route (router.go:791-791)`, `node.findStaticChild (router.go:709-709)`)
- Registration also tracks parameter complexity. `Echo.add(route Route)` has behavior `GUARD(e -> RouteInfo); PRECEDENCE(e -> err -> paramsCount)`. Because `paramsCount` is part of the registration precedence bookkeeping, parameterized routes are explicitly distinguished when routes are added. (clue: `Echo.add (echo.go:621-621)`)
- Method dispatch is separate from path overlap resolution. After the path tree chooses a candidate node, `routeMethods.find(method string, fallbackToAny bool)` dispatches by method. So “which route wins” is first a path-structure question, then an HTTP-method question. (clue: `DefaultRouter.Route (router.go:791-791)`, `routeMethods.find (router.go:213-213)`)
- `RouteNotFound` is also registered into the same routing flow as a special-case route executed when no other route is found. That means if neither a static route nor a more generic pattern wins, Echo can still fall through to an explicit route-not-found handler. (clue: `Echo.RouteNotFound (echo.go:495-495)`, `Group.RouteNotFound (group.go:153-153)`)
- What I can say confidently from File 1 is:
  1. static routes are handled through the normal router, not a side channel, (clue: `Echo.Static (echo.go:533-533)`, `Echo.StaticFS (echo.go:548-548)`, `Echo.FileFS (echo.go:591-591)`)
  2. static child lookup has a named, direct step during routing, so static segments appear to get first crack, (clue: `DefaultRouter.Route (router.go:791-791)`, `node.findStaticChild (router.go:709-709)`)
  3. parameterized routes are tracked distinctly via `paramsCount`, (clue: `Echo.add (echo.go:621-621)`)
  4. and final selection still depends on method dispatch. (clue: `routeMethods.find (router.go:213-213)`)
- What I cannot prove from File 1 is the exact ordering between parameter nodes and wildcard nodes once the static-child lookup fails, because that deeper decision seems to live inside the generic `node` / `find` logic whose bodies are not exposed here. So any claim stronger than “static first, then generic matching logic” would go beyond the clue file. (clue: `DefaultRouter.Route (router.go:791-791)`)
