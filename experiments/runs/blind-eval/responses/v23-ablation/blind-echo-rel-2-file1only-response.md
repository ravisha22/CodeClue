# v2.3 Ablation (File 1 Only): blind-echo-rel-2
Date: 2026-04-15

Echo’s router, route match types, and middleware ordering all connect through one core model: routes are registered into `DefaultRouter`, matching is done by that router with method-aware route tables, and middleware is split into pre-routing and post-match phases.

- The router is the central registry. `DefaultRouter` is described as “the registry of all registered routes for an `Echo` instance for request matching and URL path parameters,” with methods `Add`, `Remove`, `Route`, `Routes`, `insert`, and `storeRouteInfo`. (clue: `DefaultRouter (router.go:60-60)`)
- Registration funnels into that router from multiple surfaces. `Echo.Add` registers a new route and calls `add`; `Echo.AddRoute` registers a `Route` and delegates to `e.add`; `Group.AddRoute` delegates to `g.echo.add`; and `DefaultRouter.storeRouteInfo` is called by `Add`. So groups and direct route registration ultimately feed the same router. (clue: `Echo.Add (echo.go:642-642)`, `Echo.AddRoute (echo.go:617-617)`, `Group.AddRoute (group.go:172-172)`, `DefaultRouter.storeRouteInfo (router.go:538-538)`)
- Echo exposes several route match types, but they are mostly convenience wrappers over common registration. `Echo.GET`, `DELETE`, `PATCH`, `POST`, `PUT`, `TRACE`, `HEAD`, `OPTIONS`, and `CONNECT` all delegate to `Add`; `Echo.Any` registers a route for all supported methods; and `Echo.Match` registers one path for multiple methods by accumulating across the method list and calling `AddRoute`. (clue: `Echo.GET (echo.go:449-449)`, `Echo.DELETE (echo.go:443-443)`, `Echo.PATCH (echo.go:467-467)`, `Echo.POST (echo.go:473-473)`, `Echo.PUT (echo.go:479-479)`, `Echo.TRACE (echo.go:485-485)`, `Echo.HEAD (echo.go:455-455)`, `Echo.OPTIONS (echo.go:461-461)`, `Echo.CONNECT (echo.go:437-437)`, `Echo.Any (echo.go:504-504)`, `Echo.Match (echo.go:510-510)`)
- There is also a special no-match route type. `Echo.RouteNotFound` registers a “special-case route which is executed when no other route is found,” and `Group.RouteNotFound` delegates to group registration. So “no route matched” is itself representable inside the routing system. (clue: `Echo.RouteNotFound (echo.go:495-495)`, `Group.RouteNotFound (group.go:153-153)`)
- Actual request matching is done by `DefaultRouter.Route(c *Context)`, which “looks up a handler registered for method and path.” Its behavior uses precedence and an accumulating search, and it calls `findStaticChild`, `node`, and `find`. That ties path-tree traversal directly to the router. (clue: `DefaultRouter.Route (router.go:791-791)`, `node.findStaticChild (router.go:709-709)`)
- Method selection is a second layer on top of path matching. `routeMethods.find(method string, fallbackToAny bool)` dispatches by method, while `routeMethods.updateAllowHeader` accumulates allowed methods and is called when methods are set. That shows Echo’s router distinguishes path matching from final HTTP-method resolution. (clue: `routeMethods.find (router.go:213-213)`, `routeMethods.updateAllowHeader (router.go:251-251)`, `routeMethods.set (router.go:171-171)`)
- Middleware ordering is explicit and split into two phases. `Echo.Pre` adds middleware “before router tries to find matching route,” while `Echo.Use` adds middleware “after router has found matching route and before route/request handler ...”. This is the clearest statement of router/middleware ordering in the clue file. (clue: `Echo.Pre (echo.go:426-426)`, `Echo.Use (echo.go:431-431)`)
- The middleware packages reinforce that split. `AddTrailingSlash` and `RemoveTrailingSlash` are described as root-level middleware that run “before router,” meaning URI normalization belongs in the pre-routing phase. (clue: `AddTrailingSlash (middleware/slash.go:29-29)`, `RemoveTrailingSlash (middleware/slash.go:93-93)`)
- Group-level and route-level middleware both compose into the same routing model. `Echo.Group` creates a group with prefix and optional group-level middleware and calls `Use`, while route helpers such as `Echo.Add` / `Echo.GET` accept optional route-level middleware arguments. So the overall order is: pre-routing middleware -> router match -> `Use` / group middleware -> route-level handler stack. (clue: `Echo.Group (echo.go:659-659)`, `Echo.Use (echo.go:431-431)`, `Echo.Add (echo.go:642-642)`, `Echo.GET (echo.go:449-449)`)
