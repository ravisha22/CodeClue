# v2.3 Ablation (File 1 Only): blind-requests-mech-2
Date: 2026-04-15

Requests handles `Response` streaming as a lazy iterator pipeline, and it surfaces transport/decoding edge cases through dedicated response-layer exceptions rather than leaving raw lower-level errors exposed.

- A `Response` object is first built by the adapter layer. `build_response (src/requests/adapters.py:337-372)` “Builds a `Response` object from a urllib3 ...” and uses `CaseInsensitiveDict`, so headers and core response metadata are normalized as the response wrapper is created. (clue: `build_response (src/requests/adapters.py:337-372)`, `CaseInsensitiveDict (src/requests/structures.py:13)`)
- Streaming is centered on `iter_content`. `Response (src/requests/models.py:642-1041)` calls `iter_content`, and `iter_content (src/requests/models.py:801-857)` “Iterates over the response data,” calling `generate`. `Response.__iter__` simply delegates to `iter_content`, so using a response as an iterator is the same lazy streaming mechanism. (clue: `Response (src/requests/models.py:642-1041)`, `iter_content (src/requests/models.py:801-857)`, `__iter__ (src/requests/models.py:752-754)`)
- The low-level generator is where streaming branches on backend behavior. `generate (src/requests/models.py:818-839)` has behavior `BRANCH(hasattr_stream -> result, else -> result)`, so Requests adapts depending on whether the underlying response object exposes a streaming interface. (clue: `generate (src/requests/models.py:818-839)`)
- Stream-consumption edge cases are explicit. `iter_content` can raise `StreamConsumedError`, and `StreamConsumedError` means “The content for this response was already consumed.” That is how Requests prevents silently re-streaming a one-shot body. (clue: `iter_content (src/requests/models.py:801-857)`, `StreamConsumedError (src/requests/exceptions.py:128-129)`)
- Transport/chunking/decoding failures are wrapped in Requests-specific exceptions. `iter_content` raises `ChunkedEncodingError` and `ContentDecodingError` and uses `ConnectionError`; `generate` raises `ChunkedEncodingError`, `ContentDecodingError`, `ConnectionError`, and `RequestsSSLError`; and `ContentDecodingError` is specifically “Failed to decode response content.” (clue: `iter_content (src/requests/models.py:801-857)`, `generate (src/requests/models.py:818-839)`, `ContentDecodingError (src/requests/exceptions.py:124-125)`)
- Buffered helpers are built on top of the same stream path. `content (src/requests/models.py:893-909)` gets bytes via `iter_content` and can raise `RuntimeError`; `iter_lines (src/requests/models.py:859-890)` accumulates chunks from `iter_content`; and `text (src/requests/models.py:912-947)` is the unicode view of the response body. So line iteration, buffered bytes, and text all sit above the core stream reader. (clue: `content (src/requests/models.py:893-909)`, `iter_lines (src/requests/models.py:859-890)`, `text (src/requests/models.py:912-947)`, `iter_content (src/requests/models.py:801-857)`)
- Unicode decoding also has a streaming-specific helper. `stream_decode_response_unicode (src/requests/utils.py:551-565)` “Stream decodes an iterator” and accumulates results, while `get_unicode_from_response (src/requests/utils.py:578-614)` uses `get_encoding_from_headers`. That shows Requests has separate logic for incremental unicode decoding and for buffered unicode conversion informed by headers. (clue: `stream_decode_response_unicode (src/requests/utils.py:551-565)`, `get_unicode_from_response (src/requests/utils.py:578-614)`, `get_encoding_from_headers (src/requests/utils.py:526)`)
- JSON decoding is treated as its own edge case. `json (src/requests/models.py:949-982)` decodes the body as JSON and raises `RequestsJSONDecodeError`, which is distinct from transport-level `ContentDecodingError`. So malformed JSON after a successful transfer is reported differently from content-encoding failure while reading the bytes. (clue: `json (src/requests/models.py:949-982)`, `ContentDecodingError (src/requests/exceptions.py:124-125)`)
- Finally, streaming has connection-lifecycle consequences: `Response.close (src/requests/models.py:1030)` “Releases the connection back to the pool.” That means if streaming is cut short or the caller is done early, closing the response is part of handling the response safely. (clue: `close (src/requests/models.py:1030)`, `Response (src/requests/models.py:642-1041)`)
