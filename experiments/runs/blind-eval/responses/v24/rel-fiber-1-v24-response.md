# v2.4 Response: rel-fiber-1
Date: 2026-04-16

## Question
What is the relationship between the App struct, Router, and Route types in Fiber, and how do they connect?

## Answer

### Core Types

1. **App** (`App`, app.go:69) — "App denotes the Fiber application." It exposes methods: `Add`, `All`, `Config`, `Connect`, `Delete`, `Domain`, and more. This is the central application struct.

2. **Router** (`Router`, router.go:18-19) — "Router defines all router handle interface, including app and group router." This is an **interface**, not a struct, meaning both `App` and `Group` implement the `Router` interface.

3. **Route** (`Route`, router.go:45-46) — "Route is a struct that holds all metadata for each registered handler." It has a `match` method.

### How App Implements Router

`App` provides all the HTTP method registration methods that constitute the `Router` interface:

- `App.Add` (`App.Add`, app.go:953) — "Add allows you to specify multiple HTTP methods..."
- `App.Connect` (`App.Connect`, app.go:929) — delegates to `App.Add` via `DELEGATE(app.Add -> result)`
- `App.All` — registers for all methods (listed in App's methods)

Each HTTP verb method (Connect, Delete, Get, Head, etc.) ultimately delegates to `App.Add` (`App.Connect` calls: `Add`).

### Route Registration Flow

When `App.Add` is called, the route registration proceeds through an internal chain:

1. `App.Add` is called by verb methods and triggers internal registration.
2. The internal `App.addRoute` (`App.addRoute`, router.go:590) has signature `App.addRoute(method string, route *Route)` and behavior `UNWIND(defer)`. It calls `pruneAutoHeadRouteLocked` and is called by `register`. This stores the `Route` in the app's route stack.
3. `App.addPrefixToRoute` (`App.addPrefixToRoute`, router.go:355) applies a prefix to a route.
4. `App.pruneAutoHeadRouteLocked` (`App.pruneAutoHeadRouteLocked`, router.go:491) removes automatically generated HEAD routes so explicit registrations can take their place. It calls `normalizePath` and is called by both `addRoute` and `deleteRoute`.

### Route Matching at Request Time

During request handling:

1. `App.requestHandler` is the entry point (referenced in `App.next`'s called_by).
2. `App.next` (`App.next`, router.go:115) iterates over routes with behavior `PRECEDENCE(not_ok -> c -> exists); ACCUMULATE(match loop -> result)` and calls `Route.match`.
3. `App.nextCustom` (`App.nextCustom`, router.go:216) does the same for custom context types.
4. `Route.match` (`Route.match` — listed as a method of `Route`) performs the actual path matching.

### Route Removal

Routes can be removed via three methods, all calling `App.deleteRoute` (`App.deleteRoute`, router.go:443):
- `App.RemoveRoute` (`App.RemoveRoute`, router.go:417) — removes by path, calls `deleteRoute` and `normalizePath`
- `App.RemoveRouteByName` (`App.RemoveRouteByName`, router.go:430) — removes by name
- `App.RemoveRouteFunc` (`App.RemoveRouteFunc`, router.go:439) — removes by custom match function

### Group as a Router

`Group.Add` (`Group.Add`, group.go:167) also allows specifying multiple HTTP methods, and `Group.Connect` (`Group.Connect`, group.go:143) delegates to `Group.Add` via `DELEGATE(grp.Add -> result)`. Groups implement the same `Router` interface as `App`.

### App.Route — Scoped Route Definition

`App.Route` (`App.Route`, app.go:1024) allows defining routes with a common prefix inside a supplied function. Its signature is `App.Route(prefix string, fn func(router Router))` and it calls `Group` and `Name`. It panics if `fn == nil`. This method creates a Group under the given prefix and passes it (as a `Router`) to the callback function.

### The Registering Type

`Registering.Add` (`Registering.Add`, register.go:111) is another type that exposes `Add` for route registration. `Register` (`Register`, register.go:8-9) "defines all router handle interface generated by RouteChain()." The `Registering` type supports chaining via `RouteChain` — e.g., `domainRouter.RouteChain` (`domainRouter.RouteChain`, domain.go:575) creates a `Registering` instance.

### Domain Router

`domainRouter` is a parallel routing construct for domain-based matching:
- `domainRouter.Add` (`domainRouter.Add`, domain.go:530) — registers routes
- `domainRouter.Route` (`domainRouter.Route`, domain.go:584) — scoped definition, same pattern as `App.Route`, calls `Group` and `Name`
- `domainRouter.mount` (`domainRouter.mount`, domain.go:403) — attaches a sub-app to the domain router

### Mounting and Sub-Apps

`App.mount` (`App.mount`, mount.go:42) attaches another app as a sub-router, and `Group.mount` (`Group.mount`, mount.go:73) does the same at the group level. `App.MountPath` (`App.MountPath`, mount.go:103-104) returns the route pattern where the app was mounted.

### Context Access to Route

`DefaultCtx.Route` (`DefaultCtx.Route`, ctx.go:355-356) returns the matched `Route` struct with a guard: if `c.route == nil`, it returns an empty `&Route{}`. `DefaultReq.Route` (`DefaultReq.Route`, req.go:1002) delegates to `r.c.Route`. These allow handlers and middleware to inspect the matched route.

### Summary of Relationships

```
Router (interface, router.go:18)
  ├── App (struct, app.go:69) — implements Router
  │     ├── App.Add → register → App.addRoute → stores Route in stack
  │     ├── App.next/nextCustom → Route.match (dispatch loop)
  │     ├── App.Route → creates Group → passes as Router
  │     └── App.mount → attaches sub-App
  ├── Group (group.go) — implements Router
  │     └── Group.Add, Group.mount
  └── domainRouter (domain.go) — parallel domain-scoped router

Route (struct, router.go:45) — metadata per handler
  └── Route.match — used by App.next/nextCustom
```
