## Decorators build commands first, then groups dispatch subcommands

Click first turns a decorated Python function into a `Command`. The `command` decorator “creates a new `Command` and uses the decorated function” and its behavior is `UNWIND(reversed)`, so parameter metadata collected earlier is reversed into command order when the command object is created (`command`, `src/click/decorators.py:168-255`). Parameter decorators feed that metadata into the command-building step: `option` “attaches an option to the command” and calls `_param_memo`, and `argument` likewise calls `_param_memo` (`option`, `src/click/decorators.py:352-377`; `argument`, `src/click/decorators.py:324-349`; SYM `_param_memo`, `src/click/decorators.py:314`).

Nested CLIs are built around `Group`. The prompt’s `ComplexCLI` example explicitly `extends: Group`, and the examples directory also contains an `AliasedGroup` with `get_command` and `resolve_command`, showing that subcommand lookup is group-driven (`ComplexCLI`, `examples/complex/complex/cli.py:31-45`; INDEX `examples/complex/complex/cli.py`; INDEX `examples/aliases/aliases.py`). Click also forbids unsupported nesting in chain mode: `_check_nested_chain` is `called_by: CommandCollection, add_command, Group`, returns early unless the parent is a chained group with a subgroup child, and otherwise raises `RuntimeError` (`_check_nested_chain`, `src/click/core.py:73-90`; source snippet `_check_nested_chain`, `src/click/core.py L73-90`).

At runtime, parsing flows through `_OptionParser`, which calls `_match_long_opt`, `_match_short_opt`, and `_get_value_from_state` (`_OptionParser`, `src/click/parser.py:220-499`). `_match_long_opt` guards that the option exists in `self._long_opt` and raises `NoSuchOption` otherwise; `_match_short_opt` iterates over bundled short flags and likewise raises `NoSuchOption` for unknown flags (`_match_long_opt`, `src/click/parser.py:359-387`; `_match_short_opt`, `src/click/parser.py:389-427`). On Windows-style shells, `_expand_args` may preprocess argv by applying `expanduser`, `expandvars`, and `glob`, keeping the original arg if nothing matches (`_expand_args`, `src/click/utils.py:578-628`; source snippet `_expand_args`, `src/click/utils.py L578-628`).

Subcommand dispatch is group/context based. `list_commands` “returns a list of subcommand names” and delegates to `sorted`, so groups expose an ordered subcommand namespace (`list_commands`, `src/click/core.py:1784-1786`). `get_current_context` returns the current Click context, and `command_path` shows that contexts form a parent chain whose names and usage pieces are combined from root to leaf (`get_current_context`, `src/click/globals.py:20-41`; `command_path`, `src/click/core.py:642-658`; source snippet `command_path`, `src/click/core.py L642-658`). For completion-time dispatch, `_resolve_incomplete` first checks whether the incomplete token looks like an option, otherwise scans parameters from `ctx.command.get_params(ctx)`, and if nothing claims the token, returns `ctx.command` so the command/group itself can provide command-name completions (`_resolve_incomplete`, `src/click/shell_completion.py:623-667`; source snippet `_resolve_incomplete`, `src/click/shell_completion.py L623-667`).
