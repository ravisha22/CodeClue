## Relationship Between App, Router, and Route

### The App Struct

`App` (`app.go:69`) denotes the Fiber application. Its methods include `Add`, `All`, `Config`, `Connect`, `Delete`, `Domain` and more [FOCUS §App, app.go:69]. It is the top-level object that owns the routing infrastructure.

### The Router Interface

`Router` (`router.go:18`) defines the router handle interface, encompassing both the app and group routers [FOCUS §Router, router.go:18]. This means `App` and `Group` both implement `Router`, providing a unified interface for route registration.

### The Route Struct

`Route` (`router.go:45`) is a struct holding all metadata for each registered handler. It has a `match` method used during dispatch [FOCUS §Route, router.go:45].

### How App Connects to Routes

1. **Registration**: `App.Add` (`app.go:953`) allows specifying multiple HTTP methods to register a route [SYM §App.Add]. Methods like `App.Connect` (`app.go:929`) delegate to `App.Add` [FOCUS §App.Connect].

2. **Route Building**: `App.Route` (`app.go:1024`) defines routes with a common prefix inside a supplied function. It creates a `Group` and optionally sets a `Name`. It panics if the function is nil [FOCUS §App.Route]. This shows `App` creates `Group` instances to organize routes.

3. **Internal Registration**: `App.addRoute` (`router.go:590`) adds a `Route` to the app's route stack, using `UNWIND(defer)` and calling `pruneAutoHeadRouteLocked`. It is called by `register` [FOCUS §App.addRoute].

4. **Route Removal**: `App.deleteRoute` (`router.go:443`) removes routes by calling `pruneAutoHeadRouteLocked`. It is called by `RemoveRoute`, `RemoveRouteByName`, and `RemoveRouteFunc` [FOCUS §App.deleteRoute]. `App.RemoveRoute` (`router.go:417`) removes by path, `App.RemoveRouteByName` (`router.go:430`) by name, and `App.RemoveRouteFunc` (`router.go:439`) by custom match function [FOCUS §App.RemoveRoute, §App.RemoveRouteByName, §App.RemoveRouteFunc].

5. **Route Dispatch**: `App.next` (`router.go:115`) iterates through routes calling `Route.match` to find a handler. It is called by `requestHandler` [FOCUS §App.next]. `App.nextCustom` (`router.go:216`) does the same for `CustomCtx` [FOCUS §App.nextCustom]. Both use `ACCUMULATE(match loop -> result)`.

6. **Path Matching**: `RoutePatternMatch` (`path.go:155`) tests whether a path matches a Fiber route pattern [FOCUS §RoutePatternMatch]. `App.addPrefixToRoute` (`router.go:355`) prepends a prefix to a route [FOCUS §App.addPrefixToRoute].

### Group as Router

`Group` is a collection of routes sharing middleware and a common path prefix [SYM §Group, from other entries]. `Group.Add` (`group.go:167`), `Group.Connect` (`group.go:143`) all delegate to `Add` [SYM §Group.Add; FOCUS §Group.Connect]. `App.Group` (`app.go:969`) creates new sub-routers [referenced in FOCUS §App.Route calling Group].

### Domain Router

`domainRouter` provides a parallel routing hierarchy scoped to hostname patterns. `domainRouter.Add` (`domain.go:530`), `domainRouter.Route` (`domain.go:584`), `domainRouter.RouteChain` (`domain.go:575`), and `domainRouter.Connect` (`domain.go:506`) all mirror the App/Group API [FOCUS §domainRouter.Add, §domainRouter.Route, §domainRouter.RouteChain, §domainRouter.Connect].

### Registering Type

`Register` (`register.go:8`) defines the router handle interface generated by `RouteChain()` [FOCUS §Register]. `Registering.Add` (`register.go:111`) and `Registering.All` (`register.go:50`) provide fluent route registration [SYM §Registering.Add; FOCUS §Registering.All].

### Mounting Sub-Apps

`App.mount` (`mount.go:42`) attaches another app instance as a sub-router along a routing path [FOCUS §App.mount]. `Group.mount` (`mount.go:73`) does the same for groups [FOCUS §Group.mount]. `domainRouter.mount` (`domain.go:403`) mounts sub-apps on domain routers [FOCUS §domainRouter.mount].

### Context Access to Route

`DefaultCtx.Route` (`ctx.go:355`) returns the matched `Route` struct, guarding against nil by returning an empty `&Route{}` [FOCUS §DefaultCtx.Route]. `DefaultReq.Route` (`req.go:1002`) delegates to `DefaultCtx.Route` [FOCUS §DefaultReq.Route]. `DefaultCtx.App` (`ctx.go:102`) returns the `*App` reference [FOCUS §DefaultCtx.App].
